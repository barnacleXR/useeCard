# 数据导出、备份与恢复

独立的“备份管理”页提供以下功能：

- **完整业务 JSON**：账户、卡片、所有状态的账单、月度检查、关联、用户偏好和图标。金额保留 `amountMinor` 与 `currency`；不包含密码哈希、会话、设备令牌、配对码或部署密钥。此文件是业务数据导出，不是恢复文件。
- **账单 CSV**：所有账单（包括已扣款、作废），同时包含币种、最小单位整数、规范十进制字符串；支持中文与带引号/换行的备注。可疑表格公式会添加单引号前缀。
- **完整备份**：使用 SQLite 在线备份 API 获取一致快照，包含 WAL 中的数据、图标、账号与数据库内的实例配置；`.backup.ucb` 流式归档包含格式版本、应用版本、结构版本、各表数量及 SHA-256 校验和。完整备份含账号认证资料，应私密保管。

## 保存位置与自动备份

默认放在数据库所在目录的 `backups/`，正式容器默认即 `/data/backups`，与数据库一起保存在数据卷中。可用部署变量 `BACKUP_DIR` 指定其他目录；需要确保目录可写且持久化。代码不会将部署环境中的秘密写入备份；归档清单只包含格式、应用与结构版本、各表数量和校验和。

新实例默认每天 03:00（日本时间）自动备份；已有实例的自动备份设置在升级时不改变。可选择关闭、每日或每周，以及 1–365 天保留期限。服务每 30 秒检查一次；当日在设定时刻之后启动会补做一次，同一天已成功的任务在重启后不会重复。服务关闭期间无法执行任务，也不补造每一个错过日期。失败记录显示在备份管理页，15 分钟后重试。

仅超期的自动备份在自动备份成功后清理；手动备份和恢复前快照保留到手动删除。删除单个文件前会在浏览器确认。请定期下载备份并复制到另一台设备，同机备份不能防止磁盘损坏。

新归档支持不超过 **1 GiB 的数据库**，创建与恢复前检查备份目录剩余空间。浏览器按 8 MiB 分块上传，避免反向代理的单次请求限制。旧版 `.backup.json` 仍可恢复（原格式上限 64 MB），服务会在隔离临时库中迁移旧结构并校验。备份不包含部署环境文件（`.env`，含 OIDC 客户端密钥与 Apprise 网关凭证）或反向代理配置，这些需要独立备份。

## 从备份恢复

1. 在当前实例登录管理员。如果是新服务器，先完成空库管理员初始化。
2. 进入“备份管理”，选择“从备份恢复”，上传 `.backup.ucb` 或旧 `.backup.json`，输入**当前管理员密码**并勾选替换确认。
3. 服务校验文件格式、校验和、结构版本、数据库结构、完整性、外键和表记录数量，并检查目录空间。旧结构先在隔离临时库升级；高于当前服务版本的备份会被拒绝。
4. 服务进入维护状态（接口暂时返回 503），等待在途请求结束，先保存当前实例的完整快照。
5. 按外键依赖顺序在一个数据库事务中替换数据，发生错误会回滚。恢复前快照也可供后续手工恢复。
6. 成功后清除所有 Web 会话、设备会话、配对码、API Key、MCP 授权和浏览器推送订阅，关闭自动备份，并更新离线数据版本。用**备份中的管理员账号密码**重新登录并确认自动备份设置。部署地址与环境变量沿用当前服务器配置。

提醒按最新账单生成，恢复后自动重建；外部通知通道恢复后默认停用，需管理员核对后重新启用。iOS App 需要重新登录与同步以重新安排本地提醒，已安排的本地通知不会被远程取消。API Key 需重新创建，MCP 客户端需重新授权。
